## 自动验证

- Rust 默认桌面特性：35 个测试入口通过，1 个系统凭据探测按默认策略忽略。其中 notes.rs 的 9 个入口包括 8 个实际断言测试、1 个强制退出子进程辅助入口；该辅助入口本身不作为独立业务验收。
- Rust 核心无桌面特性：35 个入口通过、1 个忽略（链接 title 属性兼容修复前的这一轮；最终默认特性测试已含该修复）。
- 前端 18 个测试通过。SaveSession 验证迟到回执、序列化、组合保护、持久草稿、条件清理、显式合并与再次冲突；真实 Tiptap 组件验证导出/恢复不会产生程序性修改，以及完整链接属性。jsdom 仅补充缺失的 Range 几何 API，不据此验收真实布局或 IME。
- TypeScript strict、ESLint、Rust fmt 与 clippy（所有 target，警告即失败）通过。Vite 构建和 macOS Debug app 构建通过，bundle 约 36.99 MiB。

实际数据断言：手动保存同时保留前后快照；自动保存不产生历史；恢复推进 revision 并保留替换前稿；版本归属与旧 revision 被拒绝；修改不可变版本被触发器拒绝。资源 UPDATE 或版本 INSERT 零行时整笔正文/快照事务回滚。105 篇笔记与 106 条版本的分页无重复、无截断。

草稿测试真实写文件、同步临时文件并替换，校验 SHA-256、工作空间、格式与会话归属；过时序号不覆盖新稿，旧回执不清除新草稿，损坏文件保留并显示问题，符号链接和路径越界拒绝。恢复副本与快照事务建立，失败不留孤立 note resource；即使原稿较新或已软删除，也不会覆盖或删除它。

异常退出测试启动当前 Rust 测试二进制的子进程，经实际 PlatformService 写入笔记与恢复稿后强制 kill，重新打开同一 SQLite 与草稿目录；数据库原稿仍为 revision=1，恢复稿正文完整且通过校验。这模拟进程终止，不等同断电或磁盘硬件故障。

导出测试实际生成 UTF-8 TXT/Markdown 文件，核对中文、标题、粗体、引用、列表、链接及 HTML/Markdown 转义。拒绝工作空间内部目的位置；revision 变化后拒绝导出且原目的文件字节不变。

## macOS 实机

使用项目内忽略的隔离空间 `s02-notes-final`，从同样的真实 Rust 子进程强制终止恢复文件启动 Debug app：

1. 首页显示未提交恢复稿；对照恢复进入冲突状态，编辑器含完整中文恢复稿，不自动写正文。
2. 查看数据库稿（revision=1），显式提交合并稿后显示已保存 revision=2；SQLite 保留原稿与合并稿快照，已确认草稿被清除。
3. 中文粘贴第二稿，Cmd+S 手动保存到 revision=3；历史列表实际展示前后版本，预览恢复稿后恢复到 revision=4，正文正确，六条快照保留两个被替换的稿件。
4. 原生保存对话框分别导出中文文件名 TXT 与 Markdown；实际读取文件，逐字核对与 revision=4 保存稿一致，导出没有产生额外正文 revision。
5. 桌面发现程序切换 setEditable 的默认 update 事件会制造脏状态；改为不发事件，真实组件测试与重测确认恢复/导出保持已保存。
6. 链接格式实测发现 Tiptap 附带 title 属性被旧校验拒绝；兼容该属性并补 Rust/真实编辑器测试。重建并重启后添加 HTTPS 链接，Cmd+S 显示已保存 revision=6；SQLite href 完整、title=null，十条历史快照，恢复草稿清除。revision=5 为撤销未提交格式后的明确手动保存。
7. 窗口正常关闭；重启显示真实数量和此前笔记，重开正文与 revision 正确，原始数据保留。

这里验证的是中文粘贴、快捷键和选区操作；系统中文输入法组合输入仍待 S00 实测，不能将两者混用。Windows 实机、真正断电、缩放及大容量性能待验证。草稿两秒间隔内尚未落盘的输入仍可能丢失。
