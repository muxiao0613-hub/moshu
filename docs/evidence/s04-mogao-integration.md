## 用户范围与实现

用户明确选择“把现有墨稿的写作界面和功能迁入墨枢，使用本地 SQLite”。本轮据此覆盖早期文档的禁止复用前端限制。只读取同级墨稿，迁入 client 界面和创作编排；未修改原目录，未接旧 NestJS/MySQL、账号或计费服务，未复制环境变量、用户库和密钥。

迁入副本位于 `integrations/mogao`，保留原许可、运行时许可文本、来源哈希和修改清单。独立锁文件固定 React 18 及原前端依赖，经隔离编译嵌入平台 React 19；最终安装包不依赖同级目录、Node 服务或开发服务器。

墨枢模块中心启用墨稿后进入原书架、长篇章节写作台、短篇工作台、素材、角色对话及完善台。顶部“打开此前手动版作品”保留之前创建的作品；两种模型不自动混合。原有基础平台继续独立使用。

所有持久写入改走受控消息桥与 Rust，旧 localStorage 调用改为内存读取与 SQLite 排队写入；前端不持有 SQL、任意路径权限或明文持久密钥。桥校验同源、窗口来源和会话随机值，只暴露静态操作。AI HTTP/SSE、系统密钥、文件导出由 Rust 执行。

平台 schema=4，墨稿 schema=4，完整备份格式=1。新增模块迁移 0003/0004，既有 0001/0002 不变。正文沿用原受控 HTML 契约，原手动版 JSON 契约保留。实体归属、revision、保存前快照、幂等回执与来源失效由真实 SQLite 事务保护。

## 自动检查

默认 desktop 与 `--no-default-features` 两套 Rust 测试各 **92 passed / 0 failed / 1 ignored**；其中包含既有辅助入口，忽略项为真实系统凭据探测。新增 `mogao_studio.rs` 的 11 项使用真实 SQLite/ZIP/本机 TCP，不以“源码包含字符串”验收：

1. 九类实体的归属、revision、模块门禁与保存。
2. 正文哈希、历史快照、重复请求回执、恢复状态与密钥键拒绝。
3. 人物经历、事实、问题来源和过期处理，非法引用整体回滚。
4. 作品备份的 ID/素材标签映射与坏条目原子回滚。
5. SSE 拆分 UTF-8、usage、失败与接口地址限制。
6. 真实本机 HTTP 流式收发。
7. 提供商延迟时取消及提前取消。
8. 作者底色确认与历史追加。
9. 完整平台备份恢复迁入作品、状态和候选。
10. 候选记录持久化，不写入会话凭据。
11. 全局搜索/停用/软删除恢复，章节列表不传全书正文。

本机 HTTP 测试使用合成响应，只验证协议与取消，不宣称真实 AI 创作通过。既有 notes 强退恢复辅助测试的 ready 文件改为先写临时文件再重命名，消除父进程过早读取空 JSON 的竞态；产品笔记保存逻辑未因此修改。

前端累计 **50 项通过**，新增 4 项覆盖 SQLite 偏好/恢复稿的水合、顺序写入与失败重试，冲突远端 revision 的下一次保存，原生成消费者接收 native chunks，以及导出保留段落/字面实体并剔除活动标记。桥接流测试不等同真实提供商或所有 UI 取消组合验证。

Rust fmt、严格 clippy；平台 ESLint/strict TypeScript；迁入客户端 TypeScript；生产构建均通过。最终迁入依赖离线 `npm ci` 通过，npm audit 全部依赖 0 漏洞。日志保留于忽略的 `.tools/mogao-studio-*.log`、`mogao-clean-install.log` 和 `mogao-audit-final.json`，重现命令见 README 与依赖决策。
