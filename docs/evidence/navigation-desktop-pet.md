## 分层与数据边界

新增通用桌宠契约和平台配置服务。`platform_preferences` 的 `desktopPet` 键含 revision、enabled、alwaysOnTop、size；缺失时默认关闭。短事务和 baseRevision 检查复用平台数据约定，平台与墨稿 schema 保持 4，无新增迁移或依赖版本。个人偏好和桌宠偏好各自独立修订。

`get_desktop_pet` 返回持久设置与实际窗口显示状态；`save_desktop_pet` 保存后应用原生窗口；`pet_action` 只接受打开主窗口、收起和找回三个语义动作。配置保存成功但原生窗口失败时明确报错，页面重读配置并提供重新显示。重启时自动恢复已启用的桌宠，启动窗口失败不阻断主工作空间。

透明窗口由 Rust 创建固定 label 和固定本地 URL，不开放前端任意窗口创建、路径、URL 或 SQL。桌宠 capability 不授予通用原生窗口权限；自定义命令入口按真实调用窗口标签限制桌宠仅查询桌宠状态、执行桌宠动作和有界拖动，正文、导出、AI 和任意设置写入均拒绝。拖入文件只由主窗口处理。所有内容编辑仍只在主窗口，桌宠退出不会直接结束编辑器。

本地 SVG 可独立替换；眨眼、呼吸、摇尾和摸摸动画支持 reduced-motion。暂不提供自定义形象导入、桌面漫游、自动对话、主动提醒或开机自启。收起不会退出整个墨枢，退出墨枢会一并关闭桌宠。位置不跨重启保存（2026-10-18 起改为持久化，见下节），重新显示在当前屏幕内落位；“找回桌宠”可复位。完整备份恢复后的配置在下次启动或重新设置时应用。macOS 透明窗使用 Tauri 2.12.3 的 macos-private-api feature，本轮为本地 ad-hoc 交付，未声明 App Store 兼容或公开公证完成。

## 2026-10-18 完善：位置记忆、跨屏拖动与图片形象

本轮按用户“完善桌宠功能”和“需要哪些图片”的要求收口。范围仍是本地装饰性陪伴，不新增网络、账号或 AI。

### 行为变化

- 位置持久化：拖动结束（`pet_drag` 的 end 阶段）和“找回桌宠”后，把窗口左上角物理坐标写入 `platform_preferences` 的 `desktopPetPosition` 键；启动和重新显示时读取。位置与 `desktopPet` 的 revision 链完全分开，拖动不会让设置表单产生冲突。
- 跨屏拖动：可放置矩形改为所有显示器并集的裁剪结果，拖动中允许跨屏，同时保证整窗可达；旧位置落在已拔掉的显示器上时，启动自动收回可见区域。
- 位置写入是尽力而为：坐标超界（绝对值 > 1,000,000）拒绝，SQLite 写失败不影响本次拖动，损坏 JSON 按无记录处理并回落到默认角落。
- 互动补全：双击返回墨枢、右键/“···”菜单、休息/唤醒、打招呼、收起；拖动时使用独立的 `dragging` 形象与摆动动画。
- 形象素材：`src/platform/pet/assets/` 下的透明 PNG/WebP 按 `idle-1.png`、`happy-1.png`、`sleeping-1.png`、`waving-1.png`、`dragging-1.png` 命名（同一状态多帧用 `-2`、`-3` 递增），构建期由 `import.meta.glob` 收集并按状态帧率播放；没有素材时继续使用内置 SVG，`prefers-reduced-motion` 下停在首帧。

## 2026-10-19 继续修复顿挫与叠影（PET05 / AC32）

### 原因与实现

此前播放器在每次 rAF 都清屏、画完整人物，并在帧尾将下一帧叠加；独立绘制帧的头部存在横向偏移，因此叠加期间出现双眼/双耳，低帧率循环又不断重复重绘。现已：

- 使用 `scripts/calibrate-pet-motion.cjs` 对现有 RGBA 图集作只读分析，生成 registration.json 的 140 帧绘制变换与每图集 SHA-256。头部取轮廓上四分之一区域的 alpha 质心作横向锚点；脚底固定，待机/坐姿/阅读循环作最多 4% 纵向校准，单次弯腰、点头不锁高度。待机校准前横向跨度约 17.3 像素、阅读 19.09 像素，校准后约 0.0001 像素以内的舍入误差；这是几何锚点，不是人脸识别或形象一致性指标。
- 按所有帧的轮廓并集裁定共同适配比例与可放置锚点，优先完整保留耳朵/尾巴。脚本逐帧确认变换后的 alpha>96 轮廓仍在画布内，留约 8 像素边距。不编辑图像内容、不增加假帧，仍保留全部 20 动作 / 140 帧。
- 每次绘制只画一张完全不透明姿态，移除全人物帧混合与动作切换交叉淡化；解码期间不清空上一画面。同一源帧不重复清屏/绘制；rAF 保持经过时间推进，稳态微呼吸采用合成层轻微缩放。
- LRU 解码缓存由三张改为 32 MiB / 最多 8 项，同 URL 的请求共用 pending promise，旧的被淘汰请求失败不能删除后来重试的缓存。
