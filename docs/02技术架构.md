# 5 技术方案与工程边界

## 5.1 选定技术栈

核心语言选定 Rust；界面语言选定 TypeScript。二者按职责协作，采用 Tauri 2 桌面框架、React 与 Vite 界面、SQLite 本地数据库。首版重写全部业务实现，不要求沿用墨稿的 Electron、NestJS、MySQL 或原 TypeScript 业务代码。

| 层次 | 技术 | 职责 |
| --- | --- | --- |
| 桌面与平台核心 | Rust 与 Tauri 2 | 窗口生命周期、命令边界、文件与数据库、备份、模块状态 |
| 用户界面 | TypeScript 与 React | 页面、交互状态、编辑器、主题、可访问性 |
| 开发构建 | Vite 与 npm | 本地前端开发、资源构建及依赖锁定 |
| 数据访问 | rusqlite 与 SQLite | 参数化 SQL、事务、迁移、一致性快照 |
| 富文本 | Tiptap 开源核心 | 笔记及章节编辑，结构化 JSON 保存 |
| UI 样式 | Tailwind CSS 与语义设计变量 | 统一颜色、字号、间距和组件状态 |
| AI 网络请求 | Rust reqwest | 超时、流式处理、取消、服务地址约束 |
| 验证 | Rust 测试与 Vitest | 领域、数据与前端交互测试 |

Tauri 使用系统 WebView 承载网页界面，并提供前端调用 Rust 命令的机制；具体技术依据见第 13 节。选择 Rust 核心是为了集中约束文件、事务、并发和外部调用；React 负责编辑器与复杂页面，降低界面开发成本。该选择是工程判断，不承诺仅换语言就能改善全部性能或可靠性。

初始化时查询稳定版本与兼容要求，锁定 package-lock.json、Cargo.lock 和 rust-toolchain.toml；在决策记录中写下版本及选择日期。Tauri 2 为固定大版本，其他库不在本文硬编码补丁版本。禁止复制墨稿旧依赖版本后直接宣称新项目受支持。

SQLite 通过 Rust 访问。前端不开放任意 SQL、不操作任意磁盘路径。rusqlite 阻塞操作放入专用数据库工作线程，通过有界请求队列串行处理；长 AI 请求不持有数据库事务或连接锁。首版一个 Rust crate，内部按目录划分领域，不提前拆成大量 crates 或微服务。

## 5.2 分层与依赖方向

界面层调用 contracts 中定义的应用命令；Rust command 层负责输入校验与结果序列化；应用服务编排领域规则；repository 和文件服务执行持久化。领域规则不依赖 React、Tauri 窗口或某个 AI 提供商。

基础平台拥有项目、资料、笔记、任务、偏好、备份和模块注册。墨稿拥有作品、章节、创作设定、候选及来源规则。公共 AI 服务只处理连接、请求和结果，不包含人物、大纲或小说提示词。

文档与表格读取也属于基础平台：Rust 校验托管原件后解析 MD、DOCX、XLSX、CSV/TSV，输出版本化文档块、工作表和行列页；React 共用 DocumentPreview，不持有原始文件路径或通用文件读取能力。解析在阻塞工作线程运行，不持有数据库事务；同一服务串行读取以控制峰值内存。Office 容器先检查路径、实际展开量和完整性，不解压到磁盘，不执行脚本、宏、公式或外部关系。

内置模块把已经生成的文件字节、名称、来源和项目交给平台发布服务。模块负责写作或采集业务，平台负责资料生命周期与展示；同一原件可关联多个项目。当前阅读投影按请求生成，不作为 Office 编辑模型。Markdown 源文经 Rust 保存为独立草稿与文件版本；Word/Excel 使用本机编辑器处理完整文件，Rust 将工作副本与不可变附件分开，校验 baseRevision 后替换资料引用并建立历史。没有新增全文索引；以后新增检索投影时须明确来源版本与重建规则。

模块通过平台公开服务创建关联、取资料、提供搜索投影和调用 AI。模块之间不能导入对方内部目录、直接访问对方数据表或共享可变全局状态。平台只按模块注册信息提供通用入口，不通过 switch(moduleId) 把小说规则散布到基础功能。

内置模块属于共同信任的应用代码。Tauri capabilities 控制窗口与系统能力；同一个 WebView 内的模块标识不是安全身份，不能宣称它把恶意模块隔离。第三方模块沙箱属于未来单独设计的范围。

## 5.4 命令边界

前端使用语义命令，如 create_project、save_note、adopt_candidate、backup_workspace。不得提供 execute_sql、read_any_file 或 invoke_any_module 这类无限通用入口。Tauri capability、路径校验和领域校验需要同时存在，不能只依赖前端隐藏按钮。

成功返回实际业务结果；失败使用可序列化的 AppError，包含 code、message、retryable、requestId 和可选 details。统一错误码至少包含 VALIDATION、NOT_FOUND、CONFLICT、MODULE_DISABLED、IO_ERROR、DB_ERROR、CANCELLED、AI_UNAVAILABLE、BACKUP_INVALID。正文和密钥不得出现在错误 details。

所有写入都校验实体归属、有效状态、文本大小与基准版本。日期时间使用 UTC ISO 8601 存储，按用户系统时区显示；任务截止日按 YYYY-MM-DD 保存。ID 使用 UUID 字符串。前端 TypeScript strict 开启，Rust 生产路径避免 unwrap 和 panic。

# 6 界面与交互规范

## 6.1 信息架构

主导航为首页、项目、资料、任务、模块和设置。启用墨稿后增加“墨稿”入口，可固定到导航；从项目详情可进入关联作品。导航排序和固定状态属于平台偏好，模块不得建立另一个重复的全局导航。

项目详情含概览、关联资料、笔记、任务和模块内容。资料区统一显示文件、链接和笔记，按类型筛选。任务区提供列表与日期筛选。设置分为外观、快捷键、数据与备份、AI 连接和关于。回收站从资料及数据管理均可进入，调用同一服务。

墨稿工作区采用左侧作品及章节树、中间编辑区、右侧可收起的设定或 AI 辅助区。专注模式收起左右区域，仍保留保存状态与返回入口。不同作品切换时保持各自最后有效章节，候选与编辑会话按作品隔离。

## 6.2 视觉要求

使用语义变量定义背景、表面、正文、次要文字、边框、强调和状态色；浅色以暖白和墨色为基调，深色以低亮度中性背景为基调。强调色克制，不在正文上叠加粒子、打字机装饰或持续动画。品牌色最终可调整，布局与数据逻辑不能依赖硬编码颜色。

统一界面字号层级：页面标题 24 px、区域标题 18 px、小标题 16 px、正文 15 px、控件 14 px、辅助文字 13 px；按钮与输入框统一 40 px 基准高度。面板间距 24 px，主要间距采用 4 px 的倍数。长文正文与用户创作的标题保留自己的层级，不能为了统一 UI 抹平文档格式。字号设置范围仍为 14 至 24 px，实际设置服务与缩放验收按 B08 实施。导航与顶栏保持可见，窄窗口文档双栏改为纵向排列。

在 1280 × 800 和 1440 × 900 窗口下完整显示主流程；1024 × 720 时辅助侧栏自动收起，主页面不出现横向滚动。支持 125% 系统缩放和 150% 应用字号。中文输入法组合输入期间不得保存半个组合字符、触发错误快捷键或破坏光标。

## 6.3 必须覆盖的状态

每个列表与详情均覆盖首次空状态、加载、成功、无搜索结果、错误、重试及删除后不可访问状态。错误说明具体下一步；无权限或模块停用不能伪装成不存在。按钮不可用时说明原因，保存中不锁住继续输入。

窗口关闭、路由离开与模块停用共用保存冲刷规则。批量操作展示影响数量，失败显示失败项，可安全重试。危险动作说明被删除的数据类型，不能只显示“确定吗”。操作后提供撤销或回收站入口，永久删除除外。

## 6.4 键盘与可访问性

全局搜索使用 Command 或 Ctrl + K，新建与保存快捷键按当前页面上下文分配。设置中显示所有快捷键，检测与编辑器、系统常用动作冲突。所有交互控件可通过键盘进入，焦点可见，弹窗关闭后焦点回到来源控件，图标按钮具有文本名称。状态不能只靠颜色表达。

主流程页面提供可复用的标题、工具栏、筛选区、列表、详情及反馈结构。先验证真实数据的空状态与失败状态，再验收视觉；展示用假数据不能留在正式首页。

## 2026-10-17 资料库与写作空间补充（用户确认）

墨稿长篇、短篇与此前手动版作品自动进入资料库的“小说作品”阅读入口，显示最新保存正文与章节目录，可从资料库直接阅读并定位到同一章进入墨稿编辑。作品采用模块提供的只读实时投影，不复制出另一份权威正文；改名、保存、删除/恢复与完整备份恢复后的结果直接反映在资料库。停用写作模块保留已保存作品的资料库阅读，编辑仍须启用模块；模块数据故障显示明确错误。当前作品阅读条目不作为可移动、标签或收藏的普通附件副本。

进入墨稿与其他页面相同，默认保留平台侧栏、顶部横幅和正常布局，不自动全屏。点击“全屏”后进入原生系统全屏并展开写作区，点击“退出全屏”恢复普通页面；提供“返回资料库”和“返回模块中心”。切回资料库或模块中心仍通过既有保存/未保存表单/输入法保护，离开全屏写作时恢复普通窗口布局。

平台只定义通用模块资料查询、阅读和编辑定位契约；小说数据、章节顺序和正文转换留在墨稿模块。平台与墨稿 schema 均保持 4，不修改既有迁移，不新增重复正文或账号依赖。

## 2026-10-17 导航归纳与桌宠增补（用户新要求）

主导航固定五类，二级导航按既有页面偏好排序与固定，不变更实体路由和保存冲刷。桌宠使用同进程独立透明 WebView，只加载本地 React/SVG；原生窗口由 Rust 创建、设置、关闭。独立 capability 不授予通用窗口权限，Rust 调度按调用窗口标签限制桌宠只调用桌宠查询/动作/有界拖动，不读取正文或调用 AI。macOS 透明窗启用锁定版本 Tauri 的 macos-private-api feature；本地分发验证，不声称已完成 App Store 上架兼容。

桌宠位置存在 `platform_preferences` 的独立键，和 revision 化的设置表单解耦，拖动结束只做一次尽力写入。恢复与拖动都按“所有显示器并集减去窗口尺寸”计算可放置矩形，避免旧坐标落在已拔掉的屏幕上；指针位移按当前显示器 `scale_factor` 换算，保证不同缩放比下拖动跟手。形象层是 `PetSprite`：`src/platform/pet/assets/` 下的 PNG/WebP 通过 `import.meta.glob` 在构建期收集，按 `idle-1.png`、`happy-1.png`、`sleeping-1.png`、`waving-1.png`、`dragging-1.png` 命名分组并按帧率播放，没有素材时回退到内置 SVG，不产生运行时网络请求。


2026-10-18 形象层扩展：PetSprite 增加 reading 状态和状态中文名，图片失败按可用待机图 → SVG 回退；帧计时器跟随系统减少动态效果和文档可见性清理/重启。PetWindow 将 idle/reading/sleeping 的持续状态与 happy/waving 的短暂反馈区分，统一取消旧计时与指针会话收尾。设置页预览独立于原生桌宠状态，固定画布限制图片边界。未新增窗口权限、持久数据或网络调用。

## 2026-10-19 南华连续动作播放

动作清单集中于 `src/platform/pet/assets/motion/manifest.json`，每动作一张无损 WebP 图集；以 320×480 固定帧画布排版。`motion.ts` 限量缓存预解码图片并预载下一动作，`MotionSprite` 在 Canvas/rAF 时间轴绘制、交接前一画面，避免 React 逐帧更新。`useCompanionActions` 编排站/坐/阅读/睡眠的持续状态与短动作队列，旧序号的完成回调不能推进新动作。显示/减少动态效果沿用系统偏好与页面可见性；拖动器合并等待发送的位置并维持原生命令顺序。

名称改为南华，包括独立窗标题；没有新增原生能力、数据库格式、联网运行依赖或全局 shell 配置。本轮按用户要求不执行测试/构建，源代码和素材接入不等于观感验收。

2026-10-19 播放修复：新增 registration.json，离线从现有透明帧计算头部轮廓横向锚点、脚底基线与边界，记录图集哈希，运行时仅应用绘制变换。Canvas 每次只画一张不透明姿态，同源帧不重绘，取消全人物混合；微呼吸由合成层缩放承担。解码 LRU 缓存改为 32 MiB / 最多 8 项，同 URL 共用进行中的解码，旧解码失败不删除重试缓存。无新增原生命令、数据库、权限或运行时网络依赖。用户已通知验证，结果见实施状态与桌宠验收记录。
