# 4 墨稿小说模块重写要求

墨稿是墨枢内置的第一个业务模块。本模块独立编写小说领域模型和服务，不适配旧墨稿服务端，不共享旧数据库，不迁移登录、收费和社区系统。既有项目用于理解领域规则和风险，旧项目保持独立。

需要读取或编辑参考文档、展示生成表格时复用平台 B03 的文档/表格服务与文件版本，不在小说模块重复实现解析或 Office 编辑器。平台通用编辑与结果归档不改变 N01–N08 的创作范围；章节编辑和小说导出仍按本模块验收。

## 4.1 N01 作品与章节组织

书架支持创建、编辑、收藏、归档、软删除作品，字段包含作品名称、简介、创作目标、类型和可选封面。作品可独立存在，也可关联平台项目。支持卷和章节的有序树、新增、重命名、移动、排序及删除；排序写入事务，稳定 ID 不随标题变化。章节状态为草稿、修改中、定稿，字数口径在界面说明。恢复章节保留版本；关联大纲仍存在时恢复其关联。

首版以长篇多章节为主，短篇可使用单章节作品。独立短篇生成流程、平台预设和复杂短篇评分安排到后续版本。

## 4.2 N02 正文编辑与版本

编辑器支持基础富文本、撤销重做、段落查找、字数统计、专注模式和可调整行距；章节正文保存为 Tiptap JSON，纯文本作为搜索和模型输入投影，HTML 仅在导出或展示时生成。格式 schemaVersion 随正文记录保存。

复用 B04 的保存状态规则与持久化边界。正常退出、切章、停用模块和导出前都冲刷编辑稿；失败不得假称成功。保存携带 baseRevision，Rust 事务检查当前 revision 后写入，成功返回新 revision。冲突时保留本地稿及数据库稿供对照，不静默覆盖。首版采用单实例和单章节编辑会话，不实现协同合并算法。

手动建立版本、采用 AI 前、恢复旧版前均建立快照。恢复历史作为新的当前 revision，历史快照保留。已有保存回执期间的新输入不得被旧回执标成已保存。对崩溃可恢复草稿给出最后恢复时间；成功保存后清理相同版本的冗余草稿。

## 4.3 N03 创作设定

提供人物档案、世界观条目和大纲。人物首版包含名称、别名、描述、目标、关系说明与作者固定设定；世界观包含分类、标题和正文；大纲是可排序的树，节点可关联章节。字段均可手动维护、软删除、搜索，并可引用平台资料。关系首版以结构化关联与文字说明呈现，不建立专用图谱界面。

必须区分“计划发生的内容”和“已保存正文实际发生的内容”。大纲内容属于计划，不因与章节关联就自动成为事实。人物和世界观的修改会递增设定版本，用于检查 AI 候选有效性。

## 4.4 N04 小说导入导出

支持 UTF-8 TXT 小说导入，预览章节识别结果后确认，可手工调整分章；单文件上限 20 MB，超限明确提示。编码或章节识别失败时不创建半份作品。确认导入在本模块整体事务中完成，失败回滚。

导出作品或指定章节为 TXT 和 Markdown，保留顺序与标题，并支持模块结构化备份。平台完整备份包含墨稿全部数据及其资料关联。首版不支持旧 .mgao、旧数据库或旧备份格式；需要历史内容时由用户导出 TXT 后按普通小说导入。DOCX 小说导出作为后续独立需求。

## 4.5 N05 可选 AI 创作辅助

首版提供续写、选段润色与大纲草案三个入口。请求前选择人物、世界观、大纲、实际章节片段和用户指令，显示上下文清单与预计范围。返回内容进入候选区，用户可复制、插入或替换指定选区；候选被拒绝后不改变正文。所有模型请求经 Rust AI 服务发起，UI 不直接连接提供商。

提供一个经过真实接口验证的 OpenAI 兼容连接适配器，允许设置服务地址、模型和 API 密钥；“兼容”需按具体服务测试，不能宣称所有提供商都适用。无密钥时操作引导到设置；网络失败不锁住编辑器，取消保留已接收候选片段并标记未完成，禁止默认采用。

## 4.6 N06 候选采用与版本检查

候选保存 requestId、workId、chapterId、baseRevision、settingsRevision、操作类型及目标选区摘要。切换作品或章节时取消旧请求，迟到结果只能归入原请求，不可进入新章。

采用时在 Rust 层校验正文版本、设定版本与目标选区。任一不一致即拒绝自动替换，允许用户对照、复制或重新生成。采用成功要在一个事务中完成版本快照、正文更新和候选 adopted 标记。重复点击同一候选不能重复插入。UI 用候选 ID 控制重复采用；后端以候选状态保证幂等。

## 4.7 N07 来源与派生内容

按用户主动选择，为已保存正文生成实际摘要、人物经历候选和全书事实候选。首版全部候选需作者确认；自动批量提取、自动同步事实和全书质量评分延后。先可靠保存正文，再运行派生任务，二者不在同一数据库事务中。

每条派生内容记录来源章节、来源 revision、逐字引用、提取时间及 pending 或 confirmed 或 rejected 或 stale 状态。Rust 校验引用是否存在于指定正文版本；模型没有依据的条目只能作为建议，不能确认成正文事实。人物固定设定由作者维护，AI 建议需明确采用。

正文改写、删除或历史恢复后，关联摘要、经历和事实标为 stale；大纲不因此被删除。检索和生成默认排除 stale 内容。每次重试绑定新 revision，结果提交前再次校验；错误不会撤销正文保存。confirmed 指作者确认，不等于客观真实性。

## 4.8 N08 长篇上下文

提供一个 Rust 上下文编译器，统一处理人工选择、截止章节、已确认设定、有效事实、当前正文和历史片段的排序、预算和裁剪。续写与润色共用编译器规则，同时允许各自的任务指令。计划与实际证据在模型输入中显式分区。

历史片段首版使用本地关键词与用户固定片段，排除晚于截止章的章节，按篇章顺序保留来源。人物经历记录有效起始章，写早期章节时不注入未来经历。显示实际纳入与省略的条目；输入超过预算时先提示裁剪，不声称读取了全书。无需向量数据库，不自动上传整个资料库。

后续 N09 候选包括分场与分层生成、人物对话演练、伏笔台账、统一问题台账、质量评审和独立短篇工作台。增加前先证明手动创作及候选采用流程可靠，不能以首版范围名义全部提前实现。


## 2026-10-15 接入范围修订（用户最新确认）

用户选择将同级墨稿的现有写作界面和功能迁入墨枢，使用本地 SQLite。本修订覆盖本文关于仅作领域参考、禁止复用旧前端的约束。保留写作台、短篇、素材、人物经历、完善台与上下文流程；数据、文件、备份和 AI HTTP 请求由 Rust 执行，取消旧账号、会员计费、社区与服务器依赖。同级源目录保持原样，已有墨枢手动版作品保留访问入口。按功能记录实际迁入与验证结果，未接通项不得宣称完成。

## 2026-10-17 资料库与写作空间补充（用户确认）

墨稿长篇、短篇与此前手动版作品自动进入资料库的“小说作品”阅读入口，显示最新保存正文与章节目录，可从资料库直接阅读并定位到同一章进入墨稿编辑。作品采用模块提供的只读实时投影，不复制出另一份权威正文；改名、保存、删除/恢复与完整备份恢复后的结果直接反映在资料库。停用写作模块保留已保存作品的资料库阅读，编辑仍须启用模块；模块数据故障显示明确错误。当前作品阅读条目不作为可移动、标签或收藏的普通附件副本。

进入墨稿与其他页面相同，默认保留平台侧栏、顶部横幅和正常布局，不自动全屏。点击“全屏”后进入原生系统全屏并展开写作区，点击“退出全屏”恢复普通页面；提供“返回资料库”和“返回模块中心”。切回资料库或模块中心仍通过既有保存/未保存表单/输入法保护，离开全屏写作时恢复普通窗口布局。

平台只定义通用模块资料查询、阅读和编辑定位契约；小说数据、章节顺序和正文转换留在墨稿模块。平台与墨稿 schema 均保持 4，不修改既有迁移，不新增重复正文或账号依赖。

## 2026-10-17 导航归纳与桌宠增补（用户新要求）

墨稿入口归入“创作”分类，模块管理在同一分类；桌宠属于平台可选工具，关闭桌宠不影响小说保存、资料库阅读或 AI 候选。墨稿仍默认普通页面，显式点击全屏才展开；分类切换继续检查未保存内容。
