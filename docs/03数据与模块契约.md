# 7 模块契约与扩展规则

## 7.1 模块定义

首版模块是随应用构建的 TypeScript 页面和 Rust 领域实现。用户启用或停用功能，开发者增加模块后重新构建应用。业务模块与 Tauri 原生插件属于不同概念。

模块清单示例只描述数据，不是可直接执行的 API：

```json
{
  "id": "mogao",
  "name": "墨稿",
  "version": "0.1.0",
  "apiVersion": 1,
  "description": "本地小说创作",
  "entryRoute": "/modules/mogao",
  "requestedServices": ["resources.read", "search.publish", "ai.request"],
  "dataSchemaVersion": 1
}
```

id 唯一且不可因改名变化；apiVersion 为整数。首版只允许等于当前平台 API 版本，未来提供迁移后再支持多版本。清单必须在启动时校验，未知权限和重复 ID 拒绝注册，错误局限在模块。不存在的模块不能生成空入口。

## 7.2 生命周期

状态为 disabled、initializing、ready、disabling、error。首次启动数据库迁移按应用迁移顺序执行，模块停用不跳过其必要数据迁移。模块启用时初始化服务并注册导航、命令描述、搜索与备份参与者，全部完成才显示 ready。

停用先检查 dirty editor 与 active job，冲刷内容后在安全点取消任务，再移除导航和检索入口。不能取消的提交完成后才继续停用。停用失败回到 ready 并展示原因，不能让内容处于半注册状态。应用重启按已持久化启用状态恢复，初始化失败可从模块中心重试。Tauri 命令在构建时静态注册，运行时以模块状态校验限制调用，不实现动态卸载 Rust 代码。

## 7.3 平台公开服务

| 服务 | 模块可做的事情 | 限制 |
| --- | --- | --- |
| Projects | 读取项目及建立作品关联 | 不直接改写项目内部表 |
| Resources | 读取明确关联的资料及申请新资料 | 不扫描整个磁盘或自动上传资料 |
| Documents | 按资料 ID/revision 读取、编辑会话与文件版本、发布生成字节 | Rust 托管与版本事务；UI 不持有路径；Office 处理完整编辑与公式重算，平台阅读不执行宏/公式 |
| Jobs | 注册任务 进度 取消与结果 | moduleId 与实体作用域明确 |
| Search | 提供本模块可重建搜索投影 | 停用后清理正文索引 |
| Backup | 声明数据版本与附件引用 | 参与平台统一快照 不复制另一套全局备份 |
| AI | 调用指定连接与请求能力 | 不读取其他模块密钥 不自行保存凭据 |
| UI | 使用导航 主题与公共组件 | 不覆盖平台全局快捷键 |

首版服务是进程内明确接口与类型，不建立通用服务容器、模块 DSL 或任意消息总线。普通查询与写入优先使用直接接口；只用少数明确事件通知投影更新。

## 7.4 事件与搜索契约

事件包含 eventId、type、moduleId、entityId、revision、occurredAt、payloadVersion。事件在事务提交后发布；仅用于界面刷新或唤醒派生任务。关键一致性由数据库事务或持久任务保证，不能依赖内存事件必达。接收者按实体最新 revision 重建，不能依据迟到旧事件回退数据。

searchProjection 返回 moduleId、entityType、entityId、title、plainText、route、updatedAt、sourceRevision。平台校验路由位于模块注册范围。disabled 模块只展示公开标题和停用提示，不展示旧正文片段。恢复与重新启用后重建索引。

## 7.5 扩展验收

基础版中用开发测试模块验证注册、页面入口、独立迁移、查询、异常、停用和重新启用；测试模块不随正式产品显示。新增模块只改变注册列表、新模块目录、独立迁移和必要公开契约版本，不修改其他模块实现。若新需求需要公共能力，先记录职责与用例，再修改平台契约并执行回归。

# 8 数据模型与可靠性

## 8.1 数据目录与所有权

使用系统应用数据目录，内容分为 workspace.sqlite、attachments、drafts、backups 和 logs。应用标识在首次发布前固定。数据库元信息存 workspaceId 与 schemaVersion；附件使用内部 ID 路径，原始文件名作为元数据。前端取得资料 ID 后向后端申请访问，不把任意路径作为资源身份。

平台与模块使用同一 SQLite 数据库，以表前缀标明所有权，减少首版跨库事务。平台不得直接操作 mogao 业务表；小说仓储不越过平台服务操作平台表。仅全局迁移、备份和完整性检查可以读取数据库全局结构。

## 8.2 逻辑实体

下表是必要逻辑实体，Codex 可在不改变行为的前提下合并辅助表；DDL、索引与约束在阶段 S01 落实并写入数据字典。

| 归属 | 逻辑实体 | 必要字段与规则 |
| --- | --- | --- |
| 平台 | projects | id name description status revision deletedAt |
| 平台 | resources folders blobs | 类型 文件夹 来源 标签引用 blobId 校验值；folder 不形成环 |
| 平台 | notes note_versions | resourceId 正文 JSON schemaVersion revision；版本不可原地修改 |
| 平台 | tasks | 标题 状态 优先级 dueDate 可空 projectId revision |
| 平台 | tags entity_tags project_resources | 类型化实体引用与唯一关联；按归属校验 |
| 平台 | preferences module_states | 可版本化设置 启用状态；排除密钥 |
| 平台 | jobs search_projection | 任务状态 进度 请求归属；索引可重建 |
| AI 服务 | ai_connections | 提供商地址 模型 secretRef；不保存明文密钥 |
| 墨稿 | mogao_works project_links | 作品字段 可空平台关联 settingRevision |
| 墨稿 | mogao_volumes chapters chapter_versions | workId orderKey 正文 JSON revision；版本稳定 |
| 墨稿 | mogao_characters world_items outlines | 设定内容 revision；关联章与父节点归属明确 |
| 墨稿 | mogao_ai_candidates | 请求归属 基准版本 内容 操作类型 状态 |
| 墨稿 | mogao_derived_items | 摘要 经历 事实类型 来源章 revision 引用 状态 |

所有可编辑实体至少含 createdAt、updatedAt 和 revision。软删除实体增加 deletedAt，默认查询排除软删除。数据库开启外键检查，项目关联或层级删除不使用会误删共享内容的隐式级联。唯一性和归属不能仅靠前端验证。

## 8.3 保存与草稿规则

数据库保存是权威状态，浏览器 localStorage 只能存临时界面偏好，不能保存正文、连接密钥或充当数据库。所有写入参数化，事务尽量短。字段长度、JSON schemaVersion 和对象归属在 Rust 层校验。

保存采用乐观版本校验：UPDATE 以 id 和 baseRevision 为条件；受影响行不是一行时返回冲突。版本快照与正文替换在同一事务中进行。基础笔记和章节使用一致的 SaveReceipt，包含 entityId、savedRevision、clientEditSequence 和 savedAt；界面只把该 editSequence 之前的内容标为已保存。

草稿写入由 Rust 草稿服务负责，原子替换临时文件并带校验值、实体 ID、baseRevision 和编辑序号。草稿每 2 秒在有改动时落盘，不能保证突然断电前最后一次键入已保存；启动时显示可恢复稿并由用户选择。草稿恢复仍经过版本检查，不能覆盖比草稿更新的正文。已有保存成功回执的内容属于强验收要求。

## 8.4 附件与删除

导入先复制到临时文件、校验、重命名到 blob 目录，再提交资料与引用记录；数据库提交失败留下的孤立附件可由后台清理。资料显示成功前，文件与记录都必须存在。文件引用计数由数据库查询计算，不能依赖内存计数。

所有路径都相对应用管理根目录或来自一次明确的系统文件选择。校验规范化后的边界，拒绝路径穿越和越界符号链接。打开外部链接只允许 http 或 https。永久删除在数据库事务提交后进行附件清理，失败记录待清理任务，不回报数据恢复成功。

### 8.4.1 文档与表格原件和阅读视图

文档/表格原件仍是 resources → blobs 资料，不因读取而新建重复正文。DocumentView 返回 resourceId/sourceRevision、format、受控 Markdown 展示、Word 文档块、工作表名、单元格类型/文字/公式和行列范围；单元格显示字符串避免跨语言数值误解释。读取前后核对资料版本和有效状态，托管原件核对哈希；不把解析失败变成原文件丢失。解析投影不作为权威内容，可重新生成。

GeneratedArtifact 为内置 Rust 调用，包含 filename、bytes、source、description、folderId、projectId，不暴露任意路径或通用写盘命令。生成后先托管附件，再于短事务写入资料、来源和关联；失败清理本次新孤立字节，共享已存在字节保留。发布创建独立资料，不自动覆盖既有文件。编辑提交另通过 baseRevision 与文件版本事务替换资料引用；完整备份须包含原件、历史版本引用的字节及资料元数据，阅读视图无需重复备份。未提交会话需先处理草稿/工作副本，不得只备份旧附件后声称当前修改已备份。


### 8.4.2 文档编辑会话与文件历史

迁移 0002 增加 platform_document_sessions 与 platform_file_versions，不修改 0001。每份资料最多一个持久会话，记录 baseRevision、sourceBlobId、文件名、格式、Markdown 草稿及 editSequence；Office 副本位于应用的 editing/sessionId 目录。UI 只持有会话 ID，路径由 Rust 校验并解析，拒绝越界和符号链接；原始附件不交给编辑器。

Markdown 每两秒写 SQLite 恢复草稿，提交前再次落盘；同序号只接受同内容，旧序号拒绝。提交回执包含 savedRevision 和 clientEditSequence，迟到回执不得替换后续输入。Word/Excel 需在外部应用保存并关闭；检测常见锁文件及读取期间变动，失败保留副本。平台不截获外部应用尚未保存的内存输入，也不代替 Office 的格式兼容与重算。

文件变更先托管完整新字节，短事务校验资料归属与 revision，建立前后不可变版本，再修改 blob 引用。零行更新或快照失败须回滚并清理本次孤立字节，共享旧字节保留。恢复历史建立新 revision；活动会话存在时不允许恢复，以防同时修改。冲突另存保留原来源，不覆盖较新文件；会话只有显式结束时移除。

## 8.5 备份格式与恢复算法

完整备份采用 .moshub.zip，包含 manifest.json、workspace.sqlite 一致性快照和附件。manifest 含 backupFormatVersion、appVersion、workspaceId、schemaVersion、createdAt、模块数据版本、文件清单、大小和 SHA-256。使用 SQLite 在线备份能力或等价一致性方法；不能只复制一个仍在写入的主数据库文件。

备份时先冲刷编辑会话，进入短时写入屏障，创建数据库快照并固定对应附件引用，然后复制附件与校验。任务失败时不生成成功标记；成功后以原子重命名发布文件。backup job 的最终完成状态属于运行元信息，可以晚于内容快照。

恢复步骤为校验清单 → 受限解压到临时目录 → 检查路径 大小及总展开量 → 校验哈希与数据库完整性 → 校验所有外键和附件 → 必要时在临时库迁移 → 备份当前空间 → 关闭 DB 与编辑会话 → 原子切换目录 → 重新打开并重建索引。每步记录结果；切换失败重新打开原空间。默认展开上限 10 GB，可在用户明确选择后调整；恶意或损坏文件不会覆盖原库。

新格式版本大于应用支持版本时明确拒绝恢复，旧格式只有存在受测迁移时才接受。恢复不导入密钥，也不误称 AI 已配置。停用模块的数据仍包含在快照中。内容版本不默认截断，容量页提供用户主动清理方式。

## 8.6 数据升级

迁移使用编号 SQL 和固定执行顺序，记录版本、时间和校验值。应用升级先检查数据版本，迁移前备份，必要变更在事务内执行；已发布迁移不修改，新增修正迁移。迁移失败保持原数据并显示恢复途径；不静默降级读取。正式交付前必须用上一版本测试库验证升级和备份恢复。

## 2026-10-17 导航归纳与桌宠增补（用户新要求）

桌宠配置独立保存到 platform_preferences 的 desktopPet 键（enabled、alwaysOnTop、size、revision），旧库缺省关闭，无 SQL 迁移，平台/墨稿 schema 仍为 4。写入短事务检查 baseRevision，完整备份含配置。新增 get_desktop_pet、save_desktop_pet、pet_action、pet_drag 语义命令；主窗口仍是唯一内容编辑窗口。
